## Goal

Prove the bounded personal-context claims against exact current source and a
fresh generic workspace journey, while keeping private dogfood, transferability,
support, and general effectiveness as separate evidence claims.

## Non-Goals

- Publishing or retaining private user workspace prose, names, identifiers,
  paths, raw transcripts, or reconstructable case facts.
- Requiring colleague participation or claiming adoption to complete the
  generic implementation.
- Claiming broad specialist competence, comparative superiority, or support.

## Users & Context

- Maintainers need fail-closed evidence that the exact runtime preserves
  relevant specificity, honours all modes, and prevents leakage.
- Prospective users need a generic create/select, capture, retrieve, correct or
  delete journey that does not depend on initial-user configuration.

## Requirements (Outcome-Focused)

- R1. Freeze a synthetic case inventory covering causally relevant and
  irrelevant exact details, three context modes, persistence, retrieval,
  correction, deletion, staleness, isolation, disclosure, and specialist
  boundaries.
- R2. Bind every retained result to exact source/runtime/tooling identity and
  fail missing, stale, reused, incomplete, or hard-gate-failing runs.
- R3. Run the smallest exact-runtime behavioural set needed to support parent
  AC4, AC8, AC9, and AC10 without manufacturing a general effectiveness claim.
- R4. Build runtime and install artifacts twice and prove generic inventory,
  byte identity, and no private/evaluation/workflow leakage.
- R5. Run a fresh temporary generic workspace journey through mode selection,
  exact durable capture, later retrieval, correction or deletion, and
  cross-workspace isolation.
- R6. Retain only synthetic prompts/results or bounded technical/result classes.
  Real private dogfood remains separately authorised and never becomes public
  content.

## Acceptance Criteria (Verifiable)

- AC1: Covers parent AC4 and AC9 — exact-runtime results pass mode,
  persistence, correction, deletion, staleness, isolation, and disclosure hard
  gates with complete current identities.
- AC2: Covers parent AC8 and AC10 — matched relevant/irrelevant and

  material and reject unsupported authority.
- AC3: Covers parent AC11 — repeated runtime/install builds are byte-identical,

- AC4: Covers parent AC12 — a fresh generic workspace journey selects a mode,

  demonstrates no public or cross-workspace leakage.
