## Goal

Provide a deterministic generic personal-strategy workspace that preserves exact
details in compact indexes and linked owner-defined context, plus a safe
copy-based migration from the existing five-file contract.

## Non-Goals

- Reading or migrating any real private workspace during public tooling tests.
- Overwriting an existing workspace or modifying a source workspace in place.
- Adding hosted storage, databases, encryption systems, or access-control
  infrastructure.

## Users & Context

- New users need a useful blank workspace rather than a professional-only
  five-file shell.
- Existing users need a deterministic reviewed migration target that preserves
  source records and exact values.

## Requirements (Outcome-Focused)

- R1. The core scaffold contains `WORKSPACE.md`, `PROFILE.md`,
  `OBJECTIVES.md`, `PORTFOLIO.md`, `CONTEXTS.md`, `CLAIMS.md`,
  `DECISIONS.md`, and `CHANGELOG.md`.
- R2. Core indexes accept exact personal names, ages, amounts, dates,
  relationships, health context, financial context, projects, and goals with
  provenance, freshness, limitations, and approval metadata where applicable.
- R3. Optional linked `projects/` and `contexts/` detail files are allowed when
  declared by the core indexes; undeclared or broken internal links fail.
- R4. The builder remains deterministic and refuses an existing destination.
- R5. Migration reads an explicitly named valid five-file source, creates a new
  destination, preserves the source unchanged, copies valid legacy records
  without anonymisation, and emits a review report for new policy/profile/
  objective fields that require owner completion.
- R6. Validation rejects invalid policy, schema drift, duplicate IDs, invalid
  statuses, missing provenance/freshness/authority, secrets, evaluation
  leakage, copied strategic logic, unsafe paths, and unapproved extensions.
