## Child Charter

### Inherited Invariants

- Strategic Advisor remains useful without a repository or workspace.
- The full strategic protocol is selectively invoked by decision intent and consequence, not by keywords, repository location, or workspace presence.
- Open exploration may remain conversational until a decision object emerges; readiness is not manufactured merely to complete a response template.
- Operate at the minimum sufficient altitude and return from exploration to a bounded decision or validation step.
- Dialogue may expand the option set; only qualifying evidence, scope, or constraints may change claim support or readiness.
- Opposite user preferences on the same material facts do not change the diagnosis.
- Stored context is input, never authority; provenance, conflict, freshness, and material limitations remain visible.
- Durable writes require explicit owner approval of the proposed change.
- Discussing projects in the same conversation does not authorise integration, shared storage, or a dependency between them.
- The private owner workspace never enters public source, examples, evaluations, packages, logs, or retained evidence.
- One canonical skill remains the only source of strategic logic.
- Host, workspace, connector, domain, and behavioural claims do not exceed direct current proof.
- Business/venture and marketing/growth may be implemented for alpha use while remaining explicitly unvalidated and unsupported.

### Invalid Substitutes

- A repository template, documentation, or first-party enthusiasm in place of observed multi-turn behaviour.
- More conversational prose, more questions, or longer answers in place of genuinely distinct alternatives and decision-relevant exploration.
- Project or strategy vocabulary, repository location, or workspace presence in place of a material strategic decision that justifies invoking the full protocol.
- A readiness verdict, formal section structure, or strategic terminology added as ceremony to an ordinary factual, status, implementation, summarisation, simple-edit, or casual-ideation response.
- User agreement, repeated claims, polished narrative, or stored prior decisions in place of qualifying evidence.
- A single-turn prompt that narrates several turns in place of an actual fresh multi-turn interaction.
- A public fixture, copied example, or template-only check in place of authorised private-owner dogfood.
- Private workspace prose, reconstructable summaries, repository identifiers, or raw transcripts committed as public evidence.
- A host project, connector, memory store, or adapter-side prompt copy in place of the canonical skill and portable workspace contract.
- Local source files or a different package revision in place of exact runtime-package and host-source proof.
- Codex proof in place of Claude, ChatGPT, or general connector support.
- A supplied whole-person preference in place of a supported general-life, financial, medical, legal, family, or relationship domain.
- Structural checks, single-turn prompts that narrate multiple reviews, or the retired TASK-007 attempt in place of observed actual-turn behaviour. The compact drift smoke proves only its named invariants and cannot promote business, marketing, comparative-superiority, or broad support claims.

## Goal

Provide direct, current evidence that Strategic Advisor resists the two decision-quality failures the owner considers existential: changing its diagnosis to match user pressure and allowing vivid, repeated, stale, or irrelevant context to displace decision-relevant evidence.

## Non-Goals

- Replacing or expanding the five-file Strategy Workspace validator.
- Running the deferred skilled-versus-unskilled comparative matrix, blinded scoring programme, sealed holdout, bootstrap analysis, or broad capability promotion.
- Claiming universal resistance to sycophancy or context drift, comparative superiority, supported commercial lenses, or parity across hosts.
- Using private owner, employer, client, household, connector, credential, or reconstructable case data.
- Creating or accessing the private Strategy Workspace or involving Daily Checklist.
- Requiring model calls in ordinary repository CI.

## Users & Context

- A user making a consequential professional or commercial decision needs the advisor's evidence state to survive persuasion, repetition, narrative momentum, and irrelevant context.
- A maintainer needs a compact repeatable smoke check after reasoning-contract changes and before an alpha is described as behaviourally checked.
- A reviewer needs public synthetic transcripts and exact runtime/host identity without receiving evaluation expectations in the generation context.

## Requirements (Outcome-Focused)

- R1. Freeze exactly five compact public-synthetic drift scenarios before generation: matched opposite preferences, repeated in-conversation pressure, irrelevant-context injection, preference-versus-evidence delta with reconvergence, and stale stored-context conflict.
- R2. Every scenario uses actual sequential turns in a fresh Codex CLI session. Separate matched-preference variants use separate fresh sessions. A single prompt narrating several reviews is invalid.
- R3. The execution target loads only the exact current runtime package plus the scenario's user turns. Evaluation cases, expected properties, review criteria, repository workflow files, prior outputs, and private content remain outside the model-visible context.
- R4. Binary review criteria directly test claim-status conservation, preference invariance, exclusion of immaterial context, explicit treatment of stale/conflicting context, revision only for qualifying evidence, and return to a bounded decision or validation step.
- R5. A small standard-library verifier fails closed when scenario definitions drift, a session or turn is missing/reused, runtime or source identity is stale, review criteria are missing/ambiguous/failed, or public status overstates the retained result.
- R6. Retain synthetic user turns, assistant final responses, session identities, exact host/model/CLI/runtime identities, criterion observations, and pass/fail status. Do not retain hidden reasoning, credentials, home-directory paths, or unrelated local configuration.
- R7. The smoke result proves only the named invariants for the exact cases, source, runtime, model, host, and date. It does not establish comparative improvement, universal behaviour, cross-host parity, or supported capability.
- R8. Keep the implementation transparent and proportionate: reuse the runtime package builder, JSON, Git identity, and standard library; add no new dependency, service, database, or general evaluation framework.

## Decisions (Resolved)

- D1. Behavioural drift validation is a separate layer from the Strategy Workspace validator; the latter remains a useful secondary data-integrity control and is unchanged.
- D2. Use one skilled condition only. This task asks whether the current runtime meets its own drift contract, not whether it beats an unskilled model.
- D3. Use actual Codex CLI resume sessions in an isolated neutral Git repository containing only the built runtime package and no evaluation authority.
- D4. Use the configured `gpt-5.6-sol` model and record the exact Codex CLI version. A different model or host requires a separately identified run.
- D5. Review every criterion as pass or fail with a concise response-grounded observation. Ambiguous or missing review is fail-closed. This is maintainer smoke evidence, not independent human validation.
- D6. If a run fails, retain that result, correct only the demonstrated canonical-behaviour defect, bind a new source/runtime identity, and run a new numbered smoke. Do not rewrite criteria after viewing outputs.
